# سجل الفرع الرابع — إعادة بناء وتنظيف Alwaha-Pro
**التاريخ:** 22 نوفمبر 2026  
**الحالة:** فرع مؤقت مستقل للاختبار وإعادة التنظيم، بموافقة صريحة من مالك المشروع.  
**المستودع:** `nasreldinkbk09260-art/Alwaha-Pro`

## 1. سبب الإنشاء والاستثناء
طلب مالك المشروع إنشاء فرع رابع نظيف بعد ظهور أخطاء وتكرارات في اختبار هاتفين فعليين. هذا استثناء صريح لسياسة الفروع الثلاثة الدائمة، وليس تغييراً دائماً لأدوار `main` و`release` و`work`. لا يُحذف أي من الفروع الثلاثة ولا يُعاد تسميته. لا يُدمج الفرع الرابع إلى `release` أو `main` قبل إتمام الفحوص وقبول الجهازين.

## 3. قواعد البناء
1. كل تغيير في هذا الفرع مستقل، مع commit صغير واضح واختبار انحدار مقابل.
2. لا يُحذف زر لمجرد تكرار اسم دالته؛ تُراجع الوظيفة والسياق والواجهة الفعلية أولاً.
3. تُزال الأزرار المتكررة فعلاً إذا كانت تقدم الإجراء نفسه للمستخدم دون حاجة سياقية، حتى لو اختلفت التسمية أو معرّف الدالة.
4. تُفصل عناصر التحكم ذات السياقات المختلفة، مثل إرسال الرسالة في محادثتين منفصلتين، ولا تُعامل كتكرار لمجرد اشتراكها في معالج واحد.
5. لا يُعتمد تحليل النصوص وحده كدليل على تكرار DOM؛ يجب استبعاد قوالب JavaScript الشرطية التي لا تُعرض معاً والتحقق من DOM وقت التشغيل.
6. تُراجع الشجرة كاملة: الواجهة، معالجات الأحداث، الوحدات، التخزين، الشبكة، Supabase/RLS/SQL، وظائف Edge، Android/Capacitor، الأصول، Service Worker، البناء، الإدارة والاختبارات.
7. لا تُضعف صلاحيات أو تشفير أو خصوصية أو قيود بيانات لتجاوز خطأ اختبار.
8. نجاح CI أو محاكاة المتصفح لا يساوي اختبار هاتف حقيقي.

## 4. أول إصلاحات منفذة على هذا الفرع
- حذف زر «مشاركة التطبيق» من رأس الرئيسية.
- حذف دالة مشاركة التطبيق من الواجهة وإزالة مرجع مشاركة APK من مسار التثبيت؛ بقي تثبيت التطبيق منفصلاً.
- حذف طريقة `shareApk` من إضافة Android الصوتية وإزالة وارداتها غير المستخدمة، مع الإبقاء على توجيه صوت المكالمات.
- حذف اختصار التنبيهات من رأس الرئيسية؛ يبقى زر التنبيهات العام في شريط التنقل، لتجنب وجود مدخلين متكررين إلى مركز واحد.
- تحديث اختبارات قبول الرئيسية وفحص الإصلاح لمنع عودة زر مشاركة التطبيق.
- لم تُحذف مشاركة نص المنشور أو وسائط المحادثات؛ التغيير يخص زر مشاركة التطبيق القديم فقط.

- `npm run audit:home`
- `npm run audit:field-repair`
- `npm run audit:ui`
- `npm run audit:runtime`
- `npm run audit:fullscreen-ui`
- `npm run audit:marketplace-ui`
- `npm run audit:profile`
- `npm run audit:chat`
- `npm run audit:native-call-ui`
- `npm run audit:local-network-native`
- `npm run audit:admin`
- `npm run audit:release`
- بناء Android والتحقق من توقيع APK/AAB.

## 6. شروط القبول الميداني
- تثبيت نفس APK على هاتفين، وتوثيق الطراز وإصدار Android وبصمة APK.
- تجربة كل زر ظاهر في كل شاشة، وتسجيل الإجراء المتوقع والنتيجة الفعلية، ومنع الأزرار المكررة وظيفياً.
- اختبار الرجوع والتنقل والنوافذ والكيبورد وتدوير/تغيير حجم الشاشة والاتصال/انقطاعه.
- اختبار الحسابات والملف الشخصي والإعدادات والرئيسية والمنشورات والتعليقات والإشعارات والسوق والبيع والشراء والمحادثات والملفات والمكالمات والأصوات والألعاب وغرفة الأطفال والشبكة المحلية والإدارة.
- لا يُعلن النجاح حتى تُغلق كل الأخطاء المؤكدة أو تُسجل كوظائف مؤجلة بوضوح.

## 7. الحالة الحالية
- تم إنشاء الفرع الرابع.
- تم تنفيذ الإصلاحات الأولية أعلاه وتحديث اختبارات المصدر.
- لم يُثبت بعد نجاح CI أو APK جديد لهذه التغييرات.
- لم يُنفذ بعد اختبار الهاتفين بعد الإصلاح.
- تبقى الفروع الثلاثة الأصلية محفوظة دون تعديل.
