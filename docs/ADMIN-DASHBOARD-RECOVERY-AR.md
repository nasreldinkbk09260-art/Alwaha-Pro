# استعادة لوحة الإدارة — R5، 2 نوفمبر 2026

## ما وجدناه
- فرع GitHub `alwaha-admin-app-1.0.0` يحتوي واجهة `admin-app/index.html`، لكنه لا يحتوي في شجرته الحالية ملف `supabase/functions/admin-api/index.ts` أو ملفات migrations الأربعة.
- فحص Supabase الحي وجد Edge Function `admin-api` بحالة ACTIVE، الإصدار 5، `verify_jwt=true`، وبصمة المصدر `902c55efa123c01da1d9c18778c013373e81c2330b88e993286bc7d59697585b`.
- استعدنا نص الإصدار المنشور مباشرة من Supabase وأعدناه إلى `supabase/functions/admin-api/index.ts` في المصدر.
- سجل migrations الحي يؤكد تطبيق: `20261022155623_admin_action_logs`، `20261022155649_admin_action_logs_pending_outcome`، `20261022160030_admin_action_logs_list_access`، `20261022160159_admin_action_logs_actor_retention`.
- جدول `admin_action_logs` يحتوي `id` identity، `actor_user_id`, `action`, `target_id`, `outcome`, `details`, `created_at`؛ القيود تسمح بخمس إجراءات محددة وأربع حالات outcome. يوجد فهرسان للوقت والمنفذ.
- RLS مفعّل، لا توجد سياسات للعميل، ولا توجد امتيازات anon/authenticated؛ `service_role` فقط لديه صلاحيات الجدول.

## ما أنشأناه جديداً
- استعدنا واجهة إدارة مستقلة تحت `admin-app/`، وأضفنا شاشة سجل التدقيق التي يدعمها API بالفعل.
- أزلنا أي تلميح إلى الشبكة المحلية من خريطة لوحة الإدارة، التزاماً بقرار عدم استعادتها في المشروع.
- أنشأنا `admin-app/supabase/migrations/20261102130000_admin_action_logs_source_recovery.sql` من مخطط الإنتاج الحالي. هذا **مصدر استعادة جديد** وليس النص الأصلي للمigrations الأربعة؛ وهو idempotent ومخصص لبيئة جديدة بعد مراجعة اعتمادياتها. أضيف إلى SQL CI مع اختبار RLS/GRANT/sequence/indexes؛ لم يُنفذ محلياً. لا يعاد تشغيله على الإنتاج الحالي.
- أضفنا `audit:admin` وفحوصاً تؤكد أن الواجهة لا تقرأ جداول المستخدمين/التوثيق مباشرة ولا تحتوي service-role key.
- أضفنا workflow لبناء APK/AAB مستقل بهوية `pro.alwaha.admin` على فرع الإدارة أو فرع إصدار 3.0.2.

## الوظائف المتاحة حالياً
ملخص الحسابات والطلبات المعلقة، عرض/بحث الحسابات، قائمة طلبات التوثيق، قبول/رفض الطلبات، سجل التدقيق. كل طلب يمر عبر Edge Function التي تتحقق من JWT و`users.is_admin` وتكتب سجل التدقيق.
