## ملفات SQL التي حُفظت في الأرشيف لأنها لا تُفعّل كترحيلات جديدة

توجد الملفات التالية تحت `docs/migration-archive-unapplied/`، لا في `supabase/migrations/` النشط:
- `20261024211500_marketplace_lifecycle_reviews.sql`
- `20261027170000_require_accepted_friendship_for_messages.sql`
- `20261029121500_add_marketplace_foreign_key_indexes.sql`

هذه نسخ ذات أسماء/تواريخ قديمة موازية؛ migration history الحي يسجل تطبيق المقابل بأسماء/توقيتات مختلفة. إبقاؤها في الأرشيف يمنع إعادة تطبيق المخطط أو خلق duplicate migration. لا تحذفها قبل إنهاء مطابقة تاريخ Supabase.

## ملفات أصلية مفقودة وغير مستبعدة عمداً

1. `supabase/migrations/20261011184718_alwaha_profile_privacy_clean_start.sql`
2. `supabase/migrations/20261011184813_verification_request_profile_requirements.sql`

سجل Supabase الإنتاج يعرض هذين الإصدارين كمطبقين، لكن النص الأصلي لم يظهر في المصدر الحالي أو الأرشيفات المستعادة. ليست إزالة مقصودة. يجب استرجاع النص الأصلي من Git التاريخي أو backup موثوق ومقارنته بالمخطط الحي؛ لا تكتب SQL جديداً يحمل نفس الاسم من التخمين، ولا تحذف سجل التطبيق.

- `scripts/android/AlwahaAudioRoutePlugin.java` سقط من R5 ثم استعيد من R4 ضمن R6 ببصمة ثابتة، وهو موجود في R7.3 ويشترطه workflow.

## قاعدة التنظيف

لا يحذف شيء تاريخي أو migration أو ميزة متنازع عليها حتى نعرف: هل هو مفقود من غير قصد؟ أم استبعاد مقصود؟ وهل يملك دليلاً/اختباراً؟ يسمح بتنظيف نواتج build المؤقتة فقط (`dist`, `node_modules`, Android generated directory) من مصدر الرفع، مع إبقاء ملفات التاريخ والمراجعة في docs.
