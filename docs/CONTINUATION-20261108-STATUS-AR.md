# سجل متابعة إصلاحات Alwaha-Pro 3.0.3 — 2026-11-08

**فرع العمل:** `alwaha-pro-3.0.3-final-rebuild-20261107`
**قاعدة المصدر:** R7.5، دون اعتماد R7.4.2 كأساس ودون تعديل النسخة التجريبية العامة.

## إصلاحات أُضيفت إلى مصدر الفرع
- فصل نتائج مكالمات السوق عن صندوق مكالمات الأصدقاء؛ busy/no-answer/unavailable تُرسل إلى قناة السوق المناسبة، مع التحقق من الطرف والجلسة.
- فتح سياق صوت المكالمات بصمت حتى لا يمنع خيار الكتم تهيئة الصوت، مع منع إخراج النغمات فعلياً أثناء الكتم.
- نقل إنشاء غرف الألعاب وحركات الشطرنج وليدو وحرب الورق إلى Edge Function `game-actions`؛ يتحقق الخادم من الدور ورقم الحركة ويحسب الحالة التالية، ويُمنع العميل من الكتابة المباشرة في `game_rooms`.
- جعل حذف أرشيف السوق اختيارياً فقط بعد موافقة المشتري والبائع كلٌ على حدة، مع إمكانية سحب الموافقة؛ سجلات النزاع لا تُحذف آلياً.
- إضافة ردود محفوظة في دردشة الأصدقاء ومحادثة السوق باستخدام `reply_to_id`، مع منع RLS الرد على رسالة من زوج محادثة آخر أو من محادثة سوق مختلفة.
- إرسال إشعار `friend_request_accepted` إلى صاحب طلب الصداقة عند قبول الطرف الآخر، مرة واحدة لكل طلب، مع زر فتح المحادثة وتعليم الإشعار نفسه كمقروء.
- إضافة ملفي الرنين المحليين إلى Service Worker precache حتى يتاحا دون إعادة جلبهما من الشبكة، وفحص وجودهما وحجمهما ومعاينة المسار المحلي.
- إضافة اختبارات PostgreSQL معزولة ودوال تدقيق ثابتة/VM لهذه المسارات. نتائج كل دورة CI يجب مراجعتها على الالتزام المطابق قبل اعتبارها ناجحة.

## حالة قاعدة Supabase الحية
- لم تُطبّق أي migrations جديدة على قاعدة الإنتاج أثناء العمل.
- المطابقة الأخيرة: 23 إصداراً مشتركاً بين المصدر وسجل الإنتاج، وملف المصدر الآن 31 migration، منها 8 لم تظهر مطبقة في الإنتاج.
- الملفات الثمانية غير المنشورة: `20261101210000_marketplace_transaction_archive_and_call_auth.sql`، `20261102010000_legacy_client_privileges_hardening.sql`، `20261102100000_marketplace_retention_policy_and_cleanup.sql`، `20261102150000_products_seller_email_privacy.sql`، `20261108100000_server_authoritative_game_actions.sql`، `20261108110000_marketplace_retention_two_party_consent.sql`، `20261108120000_real_chat_message_replies.sql`، `20261108130000_friend_request_acceptance_notification.sql`.
- يبقى ملفا المصدر التاريخيان المسجلان كمطبقين في الإنتاج غير مسترجعين: `20261011184718_alwaha_profile_privacy_clean_start.sql` و`20261011184813_verification_request_profile_requirements.sql`. لا يُسمح باختلاق محتواهما أو إعادة استخدام رقميهما لترحيلات جديدة.
- بقي تحذير Auth الخاص بحماية كلمات المرور المسرّبة مفتوحاً. كذلك لم تُحذف الفهارس التي وصفها Advisor بأنها غير مستخدمة؛ قلة الاستخدام لا تثبت أنها زائدة.

## بوابات الإصدار المفتوحة
1. استعادة/توثيق مصدري الهجرتين التاريخيتين المفقودتين، ثم مراجعة تسلسل الترحيلات الثمانية واختبار dry-run على نسخة قاعدة منفصلة.
2. بعد موافقة صريحة وخطة نشر، تطبيق ترحيلات Supabase بالترتيب، نشر Edge Function `game-actions`، ثم إعادة فحص schema وRLS وRealtime وGRANTs وAdvisors.
3. تفعيل Leaked Password Protection في إعدادات Auth والتحقق من الحالة.
4. اختبار هاتفين حقيقيين: مكالمة صداقة ومكالمة سوق، رفض/انشغال/عدم رد، سماعة/ميكروفون/كاميرا، فقد الشبكة، الشطرنج/ليدو/حرب الورق، رسائل الرد، موافقة الأرشيف، وإشعار قبول الصداقة.
5. اختبار التصفح دون اتصال على تثبيت نظيف، أجهزة Android قديمة/مختلفة الذاكرة، واستهلاك البيانات والحرارة والذاكرة.
6. النسخة الاحتياطية الحالية مشفرة وتحتفظ بلقطة سحابية للقراءة، لكن الاستيراد لا يعيد كتابة السجلات السحابية تلقائياً؛ الاستعادة السحابية الانتقائية تحتاج خطة تعارضات واختبارات مستقلة.
7. التكيّف التلقائي لجودة الفيديو، المدير الذكي الكامل وتوسعة تطبيق الإدارة تحتاج عملاً واختبارات منفصلة. البلوتوث وFree Mesh ما زالا غير منفذين ولا يُقدمان كميزات عاملة.
8. لا إصدار عام ولا نشر متجر قبل نجاح أحدث CI على آخر commit، وبناء APK/AAB وتحقق التوقيع، ثم نجاح اختبار الجهازين والموافقة النهائية.

## ضوابط العمل
- لا حذف فروع أو ملفات أو migrations قديمة أثناء هذه المراجعة.
- لا تغيير بيانات المستخدمين أو قاعدة الإنتاج دون ضرورة وموافقة وخطة رجوع.
- لا نشر تلقائي ولا إعادة تفعيل وظائف المحاكاة القديمة.
- نجاح static audit أو PostgreSQL fixture لا يساوي اختبار Supabase حي أو اختبار جهاز حقيقي.
