# تقرير التدقيق والإصلاح الشامل — Alwaha-Pro 3.0.1
**التاريخ:** 30 أكتوبر 2026
**المرجع:** الإصدار العام 3.0.1 — commit الأساسي `1b8d6bc`

## الإصلاحات المنفذة في هذه الحزمة

1. **تعليق المنشورات على الهواتف القديمة:** أصبحت مهلة طلب Supabase تشمل وصول الاستجابة وقراءة جسمها JSON/النص، بعد أن كانت تُلغى فور وصول الرؤوس فقط. أضيف مسار احتياطي عند غياب `AbortController` وحدّ زمني واضح يمنع بقاء الطلب مفتوحاً بلا نهاية.
2. **استجابة الصفحة الرئيسية:** أضيفت حدود زمنية لقراءة كاش IndexedDB والجلسة، ولجلب حالة المستخدم عند رسم المنشورات. عند تعذر تحميل المنشورات يظهر مسار الخطأ وإعادة المحاولة بدلاً من الدوران المستمر.
3. **إنشاء الحساب:** أضيف قفل يمنع إرسال نموذج التسجيل عدة مرات، وتعطيل مؤقت للزر مع مؤشر دوران وعبارة «جاري إنشاء الحساب...»، ثم يعاد الزر لحالته بعد النجاح أو الفشل.
4. **شريط التثبيت داخل التطبيق:** أضيف كشف لسياق Capacitor وAndroid WebView ووضع الشاشة المستقلة لمنع عرض شريط تثبيت PWA داخل التطبيق المثبّت.
5. **مؤشر التوافق:** أضيف تقرير نسبة محلي يقدّر توفر خصائص المتصفح، مع قائمة الميزات التي قد لا تتوفر. النتيجة تقديرية وليست ضماناً لعمل الخادم أو الأذونات أو جودة الشبكة.
6. **زر توفيق الجهاز:** ينفّذ تحسينات محلية فقط: تقليل الحركة والمؤثرات، التحميل الكسول للصور، وتقليل التحميل المسبق للفيديو. يحفظ اختيار وضع الأداء على الجهاز محلياً ولا يرسل تقريراً أو بيانات جهاز إلى أي خادم.
7. **الفحوص والبناء:** أضيف `compatibility.js` إلى ملفات البناء والتخزين المسبق، وتغير اسم كاش Service Worker لإجبار النسخة الجديدة على التحديث. أضيف تدقيق توافق مستقل وربط بـ GitHub Actions، مع فحص صياغة ملفات JavaScript الخارجية وكتل JavaScript المضمنة.

## نتائج الاختبارات المحلية

- `release-preflight`: PASS
- `performance-audit`: PASS بعد تحديث اختبار اسم كاش Service Worker
- `field-repair-audit`: PASS بعد تحديث اختبار اسم الكاش
- `chat-release-audit`: PASS
- `compatibility-audit`: PASS، بما فيه فحص كتل JavaScript المضمنة
- فحص `node --check` لملفات JavaScript/ES modules: سيُسجل أدناه بعد الإعادة النهائية
- فحص بناء Android / تثبيت فعلي: غير متاح في بيئة التدقيق هذه؛ يجب أن ينفذه GitHub Actions ثم هاتف فعلي

## حد Android الأدنى — قرار تقني مهم

هذا المشروع مبني حالياً على Capacitor 8.5.2، والحد الأدنى الرسمي للـ Android runtime هو Android 7.0 (API 24). لا يصح تغيير `minSdkVersion` فقط إلى API 21 لإظهار Android 5 كمدعوم؛ لأن طبقة Capacitor ومكتباتها الأصلية لا تدعم ذلك، وقد ينتج ملف يثبت ثم يتعطل.

Android 5.0 يتطلب إطاراً أصلياً أقدم بكثير، مع إعادة تقييم المكونات والإضافات والاعتماديات واختبارات الأمان. توجد أطر قديمة تصل إلى Android 5.0 لكنها منتهية الدعم، ولذلك لم أستبدل بنية التطبيق الحديثة بها في إصلاح طارئ. Android 5.1 يختلف عن Android 5.0 في الحد الأدنى لبعض الإصدارات القديمة أيضاً. لم أضع ادعاءً زائفاً بأن APK الحالي يدعم Android 5.

**الهدف الذي تؤكده هذه الحزمة:** تحسين التوافق مع WebView والأجهزة الأقدم ضمن الحد الأصلي الذي يدعمه Capacitor الحالي، بدءاً من Android 7، مع عرض الميزات غير المتاحة بدلاً من التظاهر بأنها تعمل.

## فحوص تتطلب عوامل خارجية ولم يتم ادعاء نجاحها

- التثبيت والتشغيل على OPPO A5s Android 7، وجهاز Android حديث.
- إنشاء حساب حقيقي على Supabase، بما فيه التحقق من منع الإرسال المتكرر.
- اختبارات كاميرا/ميكروفون وأذونات النظام، ومكالمة WebRTC بين هاتفين على شبكتين مختلفتين.
- اختبار Realtime/RLS وتطبيق migrations على بيئة Supabase اختبارية؛ لم تُطبق migrations على قاعدة الإنتاج.
- اختبار نقل APK عبر ShareIt والتأكد من توقيع الحزمة وبقاء هوية التطبيق.

## حالة الجاهزية

هذه **حزمة إصلاح مرشحة للاختبار**. النجاح في الفحوص الثابتة لا يثبت أن كل ميزة تعمل في كل هاتف. لا تعتبر النسخة نهائية للنشر حتى ينجح بناء APK/AAB ثم اختبارها على OPPO A5s وجهاز حديث، بما في ذلك الحساب والمنشورات والمكالمات.
