# تقرير تجهيز إصدار Alwaha-Pro 2.8.5 — 14 أكتوبر 2026

هذا فرع تجهيز واختبار منفصل، وليس دمجًا في main أو إصدارًا نهائيًا.

## ما جرى إعداده في هذا المرشح
- خلفيات مستقلة للفضاء الافتراضي والطبيعة والتقنية والهدوء؛ حفظ الاختيار واستعادته؛ وزر استعادة الافتراضي.
- السوق: تفاصيل المنتج، والتواصل مع البائع عبر معرفه، وتعديل وحذف إعلان المالك، واستعمال قائمة أعمدة صريحة لا تتضمن البريد الإلكتروني.
- الرئيسية والريلز: خيارات تعديل/حذف تظهر لمالك المحتوى فقط، والعمليات محددة بمعرف المالك.
- إزالة الألعاب الفردية القديمة من واجهة الإصدار مع الحفاظ على غرف الشطرنج وليدو وحرب الورق الجماعية.
- زر «بدون إنترنت» السابق كان يعتمد WebRTC وSupabase Realtime وليس Bluetooth؛ لذلك جرى تعطيله وتوضيح أن البلوتوث قيد التطوير.
- إضافة فحص تمهيدي قبل البناء، وتثبيت npm من القفل، ودعم أسماء أسرار توقيع Android القديمة والجديدة.
- لم تتغير الأيقونة الأصلية icon.png ولا معرّف التطبيق pro.alwaha.app.

## ما لم يكتمل بعد
- لا يوجد Bluetooth حقيقي للدردشة أو المكالمات دون الإنترنت حتى الآن؛ نحتاج إضافة Android أصلية واختبار هاتفين.
- لم يتم تغيير قاعدة بيانات Supabase الإنتاجية.
- لم يتم بعد اجتياز GitHub Actions لهذا المرشح ولا اختبار APK/AAB على جهاز حقيقي.
- أظهر Supabase Security Advisor أن public.user_directory معرفة بصفة SECURITY DEFINER، وأن public.app_settings بلا سياسات RLS، وظهرت تحذيرات على دوال غرف اللعب ذات SECURITY DEFINER، وحماية كلمات المرور المسرّبة معطلة.
- سجل migrations للإنتاج لا يطابق كل ملفات المستودع؛ توجد إدخالات باسم alwaha_profile_privacy_clean_start وverification_request_profile_requirements بلا ملفات SQL مطابقة في هذا الفرع، ورقم migration غرف اللعب مختلف. لا تشغّل supabase db push للإنتاج قبل تسوية هذا الاختلاف.
- عمود products.seller_email ما زال موجودًا في قاعدة البيانات. استبعاده من طلبات الواجهة لا يمنع استعلام REST مباشر إذا كانت صلاحيات الأعمدة تسمح بذلك؛ يلزم ضبط grants على مستوى العمود بعد مطابقة سجل migrations.
- حذف سجل Post/Reel لا يحذف كائن Storage تلقائيًا؛ تنظيف الملفات يحتاج مسارًا يثبت الملكية قبل الحذف.

## التحقق قبل النشر
1. نجاح npm ci وnpm run audit:release وnpm run build في GitHub Actions.
2. اختبار التسجيل والدخول والمنشورات والسوق والريلز والمحادثات وغرف اللعب الجماعي على APK.
3. اختبار العزل باستخدام حسابين تجريبيين منفصلين ومراجعة RLS.
4. مراجعة الإنذارات الأمنية ومطابقة migrations قبل أي نشر على Supabase.
5. عدم اعتبار Bluetooth جاهزًا حتى تنجح دردشة ومكالمة صوتية فعليتان بين هاتفين دون الإنترنت.


## مرشح 2.8.5 — يلزم إكمال تهيئة الخادم والاختبار الفعلي

- اسم مستخدم للدخول، بريد إلكتروني اختياري، ورقم اتصال اختياري بمفتاح دولة قابل للاختيار أو الكتابة. عند غياب البريد تُستخدم Edge Function username-auth؛ يجب نشرها وتطبيق migration أولًا.
- ملف عام مبسط لكل مستخدم، وعمليات متابعة/إلغاء متابعة، وتحسين قبول طلب الصداقة الوارد.
- نغمة اتصال أصلية مولّدة داخل التطبيق، وإعداد تفعيلها/إيقافها وتجربتها. لا تحتوي الحزمة على موسيقى تجارية.
- تصحيح هوية قناة المكالمات بعد الدخول، وإضافة hook لإعداد TURN. يلزم توفير خدمة TURN موثوقة وأسرارها لنجاح الاتصالات على شبكات NAT الصعبة.
- تسجيل الخروج في نهاية قائمة الحساب، وإيضاح أن استعادة كلمة المرور الحالية بالبريد وليست برسالة SMS.

### قبل النشر العام
- طابق سجل Supabase migrations مع ملفات المستودع أولًا؛ لا تشغّل db push إذا بقي اختلاف غير مفهوم. ثم راجع وطبّق migration وانشر username-auth وcall-config.
- اختبر التسجيل دون بريد ومع بريد، والدخول، ومحادثتين فوريّتين في الاتجاهين، وطلب/قبول الصداقة، والمتابعة، ومكالمة واردة وصادرة بين هاتفين وحسابين.
- الرنة عبر WebAudio وRealtime تعمل عند تشغيل التطبيق؛ استقبال مكالمة والتطبيق مغلق بالكامل يحتاج Push Notifications/معالجة Android أصلية.
- نجاح التحليل والبناء لا يثبت أن كل زر اجتاز اختبارًا يدويًا أو أن الاتصال الصوتي نجح على جهازين.


## تحديث الواجهة والنغمة — مرشح 2.8.7

- تبسيط شاشة التسجيل إلى الاسم واسم المستخدم المقترح تلقائيًا وكلمة المرور، مع إخفاء التفاصيل الاختيارية في قسم قابل للفتح.
- إنشاء نغمة متعددة الطبقات بتوليد صوتي محلي؛ يلزم تجربة سمعية على جهاز فعلي قبل اعتمادها نهائيًا.
- حسّنت مراجعة Supabase صلاحيات الجداول التاريخية، وعرض دليل المستخدمين، وإعدادات الخادم، والفهارس وسياسات RLS، ومنعت الانضمام إلى غرفة من فئة لعبة مختلفة، وقيّدت تحديث طلب الصداقة على حقل الحالة فقط مع دمج سياسات التحديث المتوافقة.
- يلزم مطابقة سجل ترحيلات Supabase مع الملفات المحلية واختبار حسابين ومكالمة فعلية قبل الدمج في main.


## مرشح 2.8.7 — تمهيد الواجهة والصوت والأداء

- رنتان محليتان اختياريتان من الملفات التي قدمها صاحب المشروع، مع تحميل عند الطلب وعدم إضافتهما إلى التخزين المسبق لتقليل البيانات.
- أربع خلفيات WebP محلية مضغوطة، إعداد لغة عربي/إنجليزي، توفير بيانات، وتقليل الحركة.
- تخزين مؤقت في الذاكرة لمدة قصيرة لقراءات الجداول العامة فقط؛ لا يُخزّن الرسائل أو التنبيهات أو بيانات الحساب.
- أضيف مصدر SQL لترحيل notification_fail_safe المطبّق بالفعل على الإنتاج في سجل المستودع. لا تشغّل ترحيلات الإنتاج آليًا قبل استعادة مصدري الترحيل التاريخيين المفقودين.
- يبقى اختبار التسجيل، وحفظ الرسائل، والمكالمات بين جهازين مطلوبًا قبل النشر النهائي.
