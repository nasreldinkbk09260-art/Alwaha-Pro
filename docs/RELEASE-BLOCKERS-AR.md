# موانع الإصدار الرسمي — Alwaha-Pro 3.0.2 R7.5

آخر تحديث 3 نوفمبر 2026. هذه القائمة تتقدم على الموانع الأقدم في R3–R7.4.

## P0 — يجب إغلاقها قبل إعلان الإصدار الرسمي

1. **رفع R7.5 وتشغيل CI:** لم يُشغّل CI على مصدر R7.5 بعد. فرع الهدف `alwaha-pro-3.0.2-release-r7.5-20261103` يُرفع من commit R7.3 `553e1c4` بالسكريبت المرفق. يلزم نجاح run على SHA محدد.
2. **PostgreSQL SQL regression:** أُصلح fixture وأضيف اختبار محادثة السوق بلا صداقة، لكن لا نعتبره ناجحاً إلا بعد تشغيله في GitHub Actions.
3. **Web + Android build:** بناء CI السابق #48 يخص R7.3؛ يلزم إعادة البناء بعد تعديلات R7.5 وفحص package id/version والـsignatures.
4. **المحادثة الفعلية:** الإنتاج لديه الجداول والسياسات وRealtime، والقراءة الحية الأخيرة أظهرت محادثتين و3 رسائل. هذا لا يثبت نجاح تجربة مستخدم كاملة؛ يلزم حساب مشتري وبائع فعليان واختبار الإرسال والاستلام عبر REST/Realtime.
5. **حماية حذف الإعلان:** المنتج ما زال في production يقبل DELETE عبر authenticated/`products_delete_own`؛ القراءة الحية أعادت `authenticated_can_delete_products=true` ووجود سياسة الحذف.  migration R7 تسحب الصلاحية، لكنها لم تطبق.
6. **السجل/الضمان/الاحتفاظ:** snapshot/transaction/retention migrations موجودة في المصدر فقط، ولم تثبت في production.
7. **تاريخ migrations:** الملفان الأصليان `20261011184718_alwaha_profile_privacy_clean_start.sql` و`20261011184813_verification_request_profile_requirements.sql` مسجلان في production كمطبقين لكن محتواهما مفقود. لا تكتب بدائل تخمينية ولا تشغل `db push`.
8. **تجربة الجهازين:** لا دليل فعلي على video/audio/market calls/kids effects/backup restore على جهاز حديث وآخر أقدم وشبكتين مختلفتين.
9. **إغلاق الحساب ونسخة كاملة:** لا يوجد حالياً مسار حذف حساب موثق/منفذ داخل التطبيق. الخزنة المحلية تحفظ الإعدادات والمسودات ولقطات مسموحاً بها، لكنها لا تحفظ كل ملفات الوسائط الثنائية ولا تُعيد كتابة بيانات السحابة عند الاستيراد؛ لا تصفها بأنها نسخة كاملة للتطبيق.

## P1 — أمن/جودة لازمة للإغلاق

- Leaked Password Protection غير مفعلة في Supabase Auth.
- ثلاث SECURITY DEFINER functions تحتاج مراجعة صلاحيات ودوافع استخدام: `can_review_marketplace_product`, `join_game_room`, `submit_game_move`.
- فهرس `market_messages.sender_id` موجود في migration واختبار SQL، لكن القراءة الحية أكدت أن `market_messages_sender_id_idx` غير موجود في production حتى الآن. نجاح fixture المؤقت لا يثبت تطبيقه في Supabase.
- اختبار thermal/performance/echo لغرفة الأطفال ومسار صوت WebRTC لم يجر على هاتفين.
- جودة video adaptive/TURN packet loss/RTT لم تُثبت فعلياً.
- لا يوجد تنفيذ موثق لحذف الحساب حتى الآن؛ كما لم تُقبل رحلة الحساب كاملة من التسجيل إلى إدارة/تصدير/حذف البيانات يدوياً.

## P2 — تجميل/تحسينات بعد إغلاق القواعد

- الخلفيات الموسمية أصبحت أصولاً رقمية أصلية 1200×1920 وليست صوراً فوتوغرافية؛ يلزم قبول بصري على شاشات مختلفة ومراجعة التباين الفعلي تحت جميع البطاقات والنوافذ قبل اعتماد التصميم.
- يوجد أثر كرتوني محدود بشخصيتي Emoji تتبعان سحب دوائر التنقل وسقوط/عودة قبعة أو حذاء وصوت متغير؛ لم يُقبل بصرياً على الأجهزة، ولا يمثل شخصيات كاملة أو 3D.
- غرفة الأطفال الحالية 2.5D ومؤثرات آمنة محلية، وليست محرك AR/فيزياء/كسر زجاج واقعي. توسيعها لفيزياء متقدمة ليس شرطاً تقنياً لاختبار المسار الحالي، لكنه متطلب مفتوح إن كان ضرورياً قبل إطلاق المنتج.
- تطبيق الإدارة المستقل يحتاج APK منفصل/توقيع واختبار admin مقابل user، رغم نجاح audit وبناء الويب.

## ما لا يعاد فحصه بلا تغيير

فحوص R7.5 الساكنة موثقة في `QA-RESULTS-20261103-R7.5-AR.md`، وR7.3 أضاف reconciliation audit واختبار SQL للسوق بلا صداقة وفهرس sender_id؛ R7.5 أضاف اختبار تشغيل منطقي للثيمات. لا نطلب من المستخدم إعادة دورة npm audits في Termux؛ GitHub Actions يعيد الاختبارات الضرورية بعد push.

## تعريف «رسمي كامل»

يتطلب SHA CI ناجحاً، SQL regression ناجحاً، Web/APK/AAB build وتوقيعاً سليماً، مصالحة migration history ونسخة احتياطية، تفعيل إعدادات Auth اللازمة، نجاح الرسائل/الإشعارات/المكالمات على هاتفين وشبكتين، واختبار backup restore وUI/Compatibility. حتى ذلك الحين يظل R7.5 **Release Candidate Source** وليس الإصدار الرسمي.
