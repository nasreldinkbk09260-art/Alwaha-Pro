# خطة إغلاق الإصدار الرسمي — Alwaha-Pro

**نقطة العمل:** الفرع `alwaha-social-3.0.1-mobile-performance-20261020` عند الأساس `f116998da546b05b65d52bf89871de1490dcc920`.

## 1. إغلاق العيوب المؤكدة أولاً
- إصلاح نقطة إدراج فحوصات ترحيلات GitHub Actions، وإضافة ملفات ترحيلات محادثات السوق إلى المستودع.
- منع إعادة بناء خلاصة المنشورات عدة مرات بالتوازي، وإضافة حدود زمنية للطلبات الثانوية.
- فصل محادثات السوق عن دردشة الأصدقاء؛ السماح للمشتري والبائع بالمراسلة بعد تسجيل الدخول دون اشتراط صداقة.
- عدم حذف إعلان السوق حذفاً فعلياً من واجهة البائع: تحويل الإجراء إلى أرشفة حتى تبقى بيانات السلعة ومحادثات المشترين. لا يُفعّل حذف تلقائي بعد 30 يوماً أو بعد الضمان قبل بناء سجل اتفاق الضمان وآلية احتفاظ/حذف موثقة.
- عدم تعليم كل التنبيهات كمقروءة عند فتح المركز. يُعلّم التنبيه عند فتحه منفرداً، ويبقى زر «تعليم الكل كمقروء» إجراءً يدوياً مستقلاً.
- إنهاء قبول/رفض طلب الصداقة بعد نجاح تحديث قاعدة البيانات دون انتظار إعادة تحميل مركز التنبيهات وقائمة المستخدمين بالكامل.
- تغيير cache token للتطبيق وتحديث جميع اختبارات التوافق والأداء التي تتحقق منه.

## 2. مطابقة النسخ الأساسية 2.8.5–2.8.8
- إنشاء قائمة ميزات مرجعية من سجلات الإصدارات والنسخ المبنية، ثم مطابقة كل قسم وزر ومسار مستخدم مع 3.0.1.
- تصنيف كل عنصر: موجود ويعمل، موجود ومعطل، مفقود، أو يحتاج خدمة خارجية.
- عدم استعادة زر «الشبكة المحلية» أو تقديم وظيفة وهمية؛ يبقى غير مفعّل وموسوماً بوضوح حتى وجود تنفيذ واختبار حقيقي.

## 3. استكمال البيانات والتخزين المحلي
- فصل ذاكرة التخزين المؤقت للعرض عن النسخة الاحتياطية القابلة للاستعادة.
- تصميم مخزن محلي لإعدادات المستخدم ومسوداته والملفات التي يختار الاحتفاظ بها، مع حدود حجم وسياسة تنظيف وتشفير ما يلزم.
- زر نسخة احتياطية يصدّر البيانات التي يملك المستخدم حق تصديرها، مع استيراد تجريبي والتحقق من سلامة الملف.
- تأكيد واضح قبل حذف/نقل البيانات، مع ذكر العناصر التي ستفقد فعلاً. لا تُنسخ كلمات المرور أو رموز الجلسات أو مفاتيح الخدمة.

## 4. المحادثات والمكالمات
- اختبار جميع أزرار الدردشة: إرسال، تحديث، فتح الملف، المشاركة، الخصوصية، الصوت، الفيديو، الكاميرا، السماعة، الكتم، وإنهاء المكالمة.
- إكمال سجل السوق والضمان: حفظ لقطة من بيانات الإعلان داخل سجل المعاملة، تاريخ الاتفاق، مدة الضمان أو «دون ضمان»، تاريخ انتهاء الضمان، ثم أرشفة قابلة للاسترجاع وسياسة حذف متأخر بعد إشعار المستخدم.
- السماح بمكالمة البائع دون صداقة يتطلب توسيعاً مستقلاً وآمناً لقواعد إشارات WebRTC وقنوات Realtime بحيث يستند السماح إلى طرفي محادثة سوق موثقة، لا إلى تجاوز بوابة الأصدقاء.
- رفع جودة الفيديو عبر قياس الشبكة، اختيار دقة ومعدل إطارات متكيفين، مراقبة فقد الحزم والـ RTT، والتبديل المنضبط بين TURN/STUN؛ لا يُعلن نجاحها قبل اختبار جهازين وشبكتين مختلفتين.
- وضع الأطفال مشروع مستقل داخل المكالمة: ضوابط دخول وخروج، واجهة آمنة، فلاتر كاميرا، أصوات وألعاب تفاعلية، أصول محلية محسّنة، واختبارات أداء وحرارة/ذاكرة على الهواتف المستهدفة. لا يُدمج كزر تجريبي فقط.

## 5. الواجهة والتجربة
- جعل عناصر التنقل الرئيسية قابلة لإعادة الترتيب/الإخفاء/الاستعادة بإعدادات محفوظة، مع دعم قارئ الشاشة وعدم تغطية المحتوى.
- تصميم خلفيات الفصول الأربعة (الصيف/الشتاء/الخريف/الربيع) مع حركة هادئة واستهلاك منخفض، واحترام تقليل الحركة ووضع توفير البيانات.
- توحيد الألوان حسب طبيعة المكوّن وتباين مناسب للقراءة، مع مراجعة كل الأقسام والأوضاع الفاتحة/الداكنة.

## 6. بوابات الإصدار الإلزامية
1. تدقيق ساكن: JavaScript/JSON/SQL، التكرار في DOM IDs، الروابط، معالجات الأزرار، الصلاحيات، حدود الطلبات، وسياسة الكاش.
2. تدقيق قاعدة البيانات: تطابق الملفات مع سجل migrations، RLS وGRANT لكل جدول، مفاتيح وفهارس، سياسات Realtime، وظائف SECURITY DEFINER، وإعداد حماية كلمات المرور المسرّبة.
3. تدقيق استخدام كامل من التسجيل حتى حذف الحساب، مع سيناريوهات متصلة/ضعيفة/دون اتصال.
4. بناء Web وAPK وAAB في CI، وفحص مخرجات الحزمة وتوقيعها ومعرّف التطبيق.
5. اختبار فعلي على هاتفين على الأقل: جهاز Android حديث وجهاز أقدم، ثم إعادة الاختبارات بعد كل إصلاح.
6. لا يصدر ZIP رسمي إلا بعد نجاح جميع البوابات، ووجود سجل يميّز اختبارات الأتمتة عن الاختبارات اليدوية.

## حدود مثبتة حالياً
- فحوصات GitHub Actions والبناء لم تُنفذ بعد للرقعة الحالية.
- سجلات Supabase الحية تعرض أن ترحيلَي محادثات السوق مسجلان كتطبيقين، بينما ملفات SQL المقابلة غير موجودة على فرع GitHub الذي تمت مراجعته؛ يجب إعادة تثبيت الملفات في المستودع ومراجعة تطابقها مع قاعدة الإنتاج.
- فحص Supabase أظهر تحذيراً بشأن حماية كلمات المرور المسرّبة، وتحذيرات مراجعة لثلاث وظائف `SECURITY DEFINER`، ومؤشر أداء لفهرس مفقود على `market_messages.sender_id`. لا تُعالج هذه التحذيرات بحذف عشوائي أو تعطيل ميزات؛ تُراجع وتغلق بقرارات موثقة.
- لم يُجر اختبار جهازين أو بناء Android محلي في هذه البيئة، لذلك لا يمكن اعتماد ZIP رسمي نهائي منها الآن.
